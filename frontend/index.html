表级缺口
            
              —— 决定「这张表能不能被找对」

          

            
          

        

        

          ★ 字段级缺口管「这一列怎么算对」，表级缺口管「这张表能不能被找对」：

          · 缺业务注释 → 检索只能拿英文表名去匹配，业务俗称（"资金流水表"）完全对不上；

          · 缺业务实体 → 语义路由认不出业务对象，用户用俗称提问时匹配不到这张主表。

          两样需要的输入都是同一份字段清单，所以 AI 一次就能起草好 ——
          生成后直接生效、进 RAG，你复核时改一遍就转为人工版（AI 不再覆盖）。
        

        

        

        

          

        

      


      

        判断依据：① 字段是枚举型（用真实数据的去重值个数判断，≤30 个才算 ——
        名字像"type"但实际有几万个值的，会被正确排除）② 注释里没说清取值含义
        ③ 也没配数据字典（配了就说明编码含义已经解决，不再重复提醒）。
      

      

    


    
    

      
      

        
        
      


      
      

        

          ★ 输入一段业务口径 / 逻辑描述，AI 会自动判断它属于哪类知识
          （P1 指标 / P2 实体·关系 / P3 字段注释·字典 / P4 文档），并自动录入到对应注册表。
          例如：「保司订单就是 need_insurance=1 的订单，其中 0 否 1 是」。

优化建议

          
        

        

          模型会读「问题反馈」里的待处理记录，给出「该改哪条 prompt / 补哪条字段注释」的草稿。
          建议不会自动生效 —— 你确认或改过之后才落地，改错了是人改的，不是机器偷偷改的。
        

        

      

    

  


  
  

    

      ★ 权限是两条防线：这里控制「AI 能看见哪些表」，数据库侧还要用「只读账号 + 表级授权」兜底。
      改完点「重建索引」生效。
      

        开放访问权限时自动「开荒」：系统会读这张表的字段清单，一次生成两样东西 ——
        表业务注释（让检索能按业务语义找到它）与业务实体登记
        （让语义路由认出"用户说的业务对象"是哪张主表）。
        两样都直接生效并进 RAG，且带「AI 生成」标记；
        你在「知识管理 → 表结构信息」/「知识治理 → 语义注册表」里改一遍，
        就转为人工版，AI 之后不再覆盖。
