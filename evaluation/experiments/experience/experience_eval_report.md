## ⚠️ 归因约束（读数前必看）

1. **同题不同解**：生成阶段调用大模型，温度非 0，同一道题每次生成的 SQL 不完全相同。因此综合通过率 / SQL 片段命中率的跨组差异**包含随机波动**，单轮不能作为机制收益的证据。
2. **召回也带随机性**：适用性硬校验依赖模型识别出的「表集合 / 指标集合」，识别结果本身有波动，会连带影响黄金命中率（同一道题在不同组可能命中不同数量）。
3. **只有开关级指标可强归因**：`exp_case_hit_rate` 从 0 变为非 0、`exp_failure_hit_rate` 随 `EXP_FAIL_PREVENT` 由 0 变为非 0 —— 这类「0 → 非 0」的跳变才是接线成功的可靠证据。
4. **D 组需要单独核实**：若规则表为空（`sql_experience_rules` 无已发布规则），D 组优于 B/C 组**不得归因于经验规则**，只能视为随机波动。
