### 2.2 前端实现方式（不引入新框架）

沿用现有**原生 JS 单页 + switchTab** 机制，做两级扩展：

1. **导航组 → 二级项**：把现有平铺的 `nav-item` 包进 `nav-group`，增加「分组标题可折叠」与「二级项」层级（`core.js` 的 `switchTab` 不改核心逻辑，仅增加二级项渲染）。
2. **页面内二级 Tab**：沿用现有 `kbSwitchModule` 模式（已在知识资产/知识治理页验证），语义建模、知识治理、AI 评测页继续用页面内 Tab。
3. **三栏布局**（本体建模）：左侧对象树 + 中间关系画布 + 右侧属性编辑器。画布用**原生 SVG**（与现有语义关系图一致），不引入 D3/ECharts 等重库；若后续需要更丰富图表，优先在单个页面内按需引入轻量图表库。
4. **`data-tab` 保持不变**：旧 15 个 `data-tab` 值（ask/fav/review/domain/kb/gov/semantic/feedback/exp/golden/dash/prompt/tables/users/perm）全部保留，新增页面新增 `data-tab`（如 `ontology`/`lineage`/`datasource`/`monitor`/`analysis`/`report`）。**旧 URL/书签/快捷键不失效。**

## 交付物 ③ 数据模型设计

### 3.1 设计总原则

**最大化复用现有表，新增表只补「现状缺失的结构化维度」，禁止无必要重复存储。** 方案第八阶段列的 13 张表名，按下表映射到「复用 / 加列 / 新增」：

| 方案建议表 | 落地决策 | 说明 |
|---|---|---|
| `business_domains` | **复用 `data_domains`** | 已有 name/display_name/owner/domain_type/department，无需新表 |
| `ontology_entities` | **复用 `entities`** | 已有 primary_key/grain/治理字段，加列补「英文标识/关联属性」 |
| `ontology_attributes` | **新增** | 实体↔属性映射（属性本体复用 column_comments/dict_entries） |
| `ontology_relations` | **复用 `relationships`** | 已有 join_type/cardinality/from_columns/to_columns |
| `ontology_rules` | **新增** | 业务规则登记（引用 metric_constraint/sql_rules/prompts） |
| `semantic_models` | **复用 `semantic_models`** | 已有 model_json 快照 + version |
| `semantic_model_tables` | **新增** | 关系模型的「物理表清单 + 主表 + 粒度」显式化 |
| `semantic_model_joins` | **新增** | 表级 Join（主表/关联表/基数/关联键/粒度） |
| `semantic_metrics` | **复用 `metrics`** | 加列 `metric_category`（atomic/derived/composite）+ `metric_code`（英文标识） |
| `semantic_dimensions` | **新增** | 维度独立成表（从 column_comments.dimension_type 派生） |
| `semantic_versions` | **复用 `semantic_model_versions`** | 已覆盖版本快照 |
| `semantic_publications` | **新增** | 发布记录（谁在何时发布/撤销哪个语义对象） |
| `semantic_asset_references` | **复用 `semantic_registry` + `topic_assets`** | 已覆盖跨资产引用登记 |

> 即：13 张建议表里 **7 张复用、2 张加列、6 张新增**（ontology_attributes / ontology_rules / semantic_model_tables / semantic_model_joins / semantic_dimensions / semantic_publications）。新增的 6 张全部是「引用/映射/登记」表，不复制资产本体。

### 3.2 新增表结构（草案）

所有新增表统一带治理元数据：`id`（稳定 ID）、`status`、`source`、`version`、`owner_id`、`created_at`、`updated_at`、`updated_by`、`approved_at`、`approved_by`。所有引用用 `stable_key`/`id`，**不用名称做模糊关联**。

```sql
-- 1) 实体属性：Object 的 Attribute 登记（属性本体在 column_comments/dict_entries）
CREATE TABLE ontology_attributes (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    entity_key    TEXT NOT NULL,          -- 关联 entities.stable_key（ID 引用）
    attr_type     TEXT NOT NULL,          -- column（字段）/ dict（字典）/ derived（派生）
    attr_key      TEXT NOT NULL,          -- column_comments.stable_key 或 dict_entries.stable_key
    label         TEXT,                   -- 属性业务名
    is_key        INTEGER DEFAULT 0,      -- 是否主键/关联键
    UNIQUE(entity_key, attr_type, attr_key)
);

-- 2) 业务规则：Rule 登记（规则本体引用 metric_constraint / sql_rules / prompts）
CREATE TABLE ontology_rules (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    entity_key    TEXT,                   -- 关联实体（可为空=全局规则）
    rule_type     TEXT NOT NULL,          -- metric_constraint / sql_rule / join_rule / biz_rule
    rule_ref      TEXT NOT NULL,          -- 引用的规则本体键（metric_constraint.constraint_id 等）
    description   TEXT
);

-- 3) 关系模型的物理表清单
CREATE TABLE semantic_model_tables (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    model_key     TEXT NOT NULL,          -- 关联 semantic_models.name / business_subjects.name
    table_name    TEXT NOT NULL,          -- 物理表名
    role          TEXT NOT NULL,          -- primary（主表）/ related（关联表）/ satellite（卫星表）
    grain         TEXT,                   -- 数据粒度
    UNIQUE(model_key, table_name)
);

-- 4) 表级 Join（关系模型画布的显式建模）
CREATE TABLE semantic_model_joins (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    model_key     TEXT NOT NULL,
    from_table    TEXT NOT NULL,
    to_table      TEXT NOT NULL,
    join_type     TEXT NOT NULL,          -- inner / left / right / full
    cardinality   TEXT NOT NULL,          -- 1:1 / 1:N / N:1 / N:M
    from_columns  TEXT,                   -- 关联键（JSON 数组）
    to_columns    TEXT,
    join_sql      TEXT,                   -- 完整 join 子句
    pre_agg_required INTEGER DEFAULT 0
);

-- 5) 维度
CREATE TABLE semantic_dimensions (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    dimension_key TEXT NOT NULL UNIQUE,   -- 稳定 ID（英文标识）
    name          TEXT NOT NULL,          -- 维度名称
    dimension_type TEXT,                  -- time / region / status / type / channel / other
    entity_key    TEXT,                   -- 对应实体
    source_table  TEXT,                   -- 物理表
    source_column TEXT,                   -- 物理字段映射
    model_key     TEXT,                   -- 所属关系模型
    hierarchy     TEXT,                   -- 维度层级（JSON，如 年→季→月）
    analyzable    INTEGER DEFAULT 1,
    permission_scope TEXT
);

-- 6) 发布记录
CREATE TABLE semantic_publications (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    asset_type    TEXT NOT NULL,          -- entity / metric / dimension / model / relationship
    asset_key     TEXT NOT NULL,          -- 资产稳定 ID
    action        TEXT NOT NULL,          -- publish / revoke
    operator      TEXT,
    created_at    TEXT
);
```

### 3.3 现有表加列（不改列、只加列）

| 表 | 加列 | 用途 |
|---|---|---|
| `entities` | `entity_code` TEXT | 实体英文标识 |
| `metrics` | `metric_code` TEXT、`metric_category` TEXT（atomic/derived/composite） | 指标英文标识 + 三分类 |
| `relationships` | （无） | 已有 join_type/cardinality/from_columns/to_columns 足够 |

> 加列走 `ALTER TABLE ... ADD COLUMN`（幂等，`config_store._ensure_ready` 已用此模式），历史行填 NULL 或按规则回填（如 metric_category 从 depends_metrics/expression 推导），不凭空造数。

### 3.4 兼容映射（旧资产 → 新语义层）

| 旧资产 | 映射到新语义对象 |
|---|---|
| `entities`（业务实体） | 本体 Object；其 `table_name` → 关系模型的物理表；`grain` → 数据粒度 |
| `relationships`（实体关系） | 本体 Relation；其 `join_sql` → 关系模型的表级 Join（解析或显式登记） |
| `metrics`（指标） | 语义指标；按 depends_metrics/expression 归入原子/衍生/复合 |
| `column_comments.dimension_type` | 语义维度（派生为 semantic_dimensions） |
| `dict_entries` | 实体属性（字典类 Attribute） |
| `metric_constraint` | 本体 Rule（指标约束类） |
| `topic_assets` / `semantic_registry` | 跨资产引用（逻辑视图血缘的底层数据） |

**迁移时保留原始 ID 及引用关系**：所有映射都是「登记/引用」，不改原表主键，不破坏 `stable_key` 指向。

### 4.2 数据库迁移策略

1. **备份**：每次迁移前 `cp agent_config.db agent_config.db.bak-semantic-YYYYMMDD-HHMMSS`（项目已有 `.bak-*` 备份惯例，沿用）。
2. **幂等迁移脚本**：新增 `migrate_semantic_center.py`，内部只做 `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ADD COLUMN`（复用 `config_store._ensure_ready` 模式），可重复执行，不删列不重建表。
3. **回填**：`metric_category` 从 `depends_metrics`/`expression` 推导；`semantic_dimensions` 从 `column_comments.dimension_type` 派生——回填脚本独立、只读源表、幂等。
4. **迁移前预检**：迁移前跑 `test_imports.py` + `check_consistency.py` 确认基线绿灯。

### 4.3 回滚方案

| 变更类型 | 回滚手段 |
|---|---|
| 前端页面/导航 | 前端是静态文件，直接 `git checkout` 或还原 `frontend/` 目录即可，无数据影响 |
| 新增表/加列 | 反向：加列不删、新表不删（表/列是只增不改，无需回滚）；若必须回滚，删掉新增表即可，原表无改动 |
| 取数链路融合 | `SEMANTIC_MODEL_ENABLED` 开关（config 已有）一键关闭，回退到纯 P0~P4 检索 |
| 全量回滚 | 用迁移前备份 `agent_config.db.bak-semantic-*` 覆盖恢复 |

### 4.4 安全红线（迁移与实施必须遵守）

1. **AI 生成内容一律 `status=candidate`**，经人工复核才 `approved`；待审核内容**不进取数检索**（现有 `get_visible_knowledge_ids` 已实现，复用）。
2. **未验证 SQL 不进 Golden 库**：AI 建模产出的 SQL 走 `sql_validator` + 人工确认，才可 promote 为 Golden/经验。
3. **不建第二套语义存储**：所有新增表是「引用/映射/登记」，资产本体仍在原 7 张知识表。
4. **每个阶段独立可回滚**：阶段间不耦合，任何阶段出问题可单独回退不影响已上线的阶段。

## 五、关键决策（已拍板，2026-11-16）

1. **业务域层级** → ✅ **保留两层**：业务域（data_domains）→ 业务主题（business_subjects）。业务主题等价于 DataBuddy 的「业务标签」概念。
2. **关系模型载体** → ✅ **业务主题即关系模型**：一个业务主题 = 一个关系模型，复用 business_subjects + semantic_models，不另起炉灶。
3. **本体 Object 载体** → ✅ **Object = entities 增强视图**：属性=字段注释映射，关系=relationships，规则=metric_constraint，属性/规则用新增映射表登记，避免两套实体。
4. **表级 Join 来源** → ✅ **新增 semantic_model_joins 显式建模为主**，迁移时从 relationships.join_sql 解析回填一次。
