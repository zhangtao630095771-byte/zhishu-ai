## 一、实施内容

### 1.1 AI 智能建模（业务场景 → 完整语义模型）

新增 `ai_ingest.model_scenario(text)`：自然语言描述业务场景 → LLM 生成**业务主题 + 实体 + 关系 + 指标 + 维度**，全部落库「待审核」。

| 变更 | 内容 |
|---|---|
| `ai_ingest.py` | 新增 `build_scenario_prompt` + `model_scenario`；`_apply` 支持 `dimension` 类型 |
| `semantic_modeling.upsert_dimension` | 支持 `source` 参数：AI → `candidate`，人工 → `approved` |
| `server.py` | 新增 `POST /api/modeling/ai-model` |
| 前端 | 语义建模页新增「✨ AI 智能建模」入口 |

**三入口（方案第六阶段）对应：**
1. **自然语言描述业务场景** → `POST /api/modeling/ai-model`（本次新增，整链建模）
2. **导入历史 SQL/指标/知识** → 复用现有 `/api/kb/ai-ingest` + `/api/kb/ingest-sql` + OSSIE 导入
3. **专业模式手动建模** → 本体建模 + 语义建模页（阶段二/三已建）

### 1.2 取数融合（正式语义资产接入 Agent）

**现状已实现**（阶段七验证并补测试，未改主链路）：
- `agent.py:790` 已有 `SEMANTIC_MODEL_ENABLED` 开关 + `business_domain_service.build_context_block` 注入
- `config_store.get_visible_knowledge_ids` 治理准入：`approved` 可见、`candidate` 仅非严格模式可见
- AI 录入的实体/指标/关系/维度均 `source=ai → status=candidate`，**不直接生效**

**铁律落实（`test_semantic_center.py` 5 项断言验证）：**
1. AI 维度 → `candidate` ✅
2. AI 不覆盖人工维度 ✅
3. `approved` 可见 ✅
4. 严格模式下 `candidate` 不进生产检索 ✅
5. 整链建模 Prompt 覆盖全类型 ✅
