# 知数AI · 持续优化机制（Continuous Improvement）

> 目标：让「最新 / 最准确 / 最适合我们公司」不是一次性状态，而是**可持续逼近的机制**。
>
> 核心判断：**AI 取数系统不会"优化完就稳定"，它会持续漂移。**
> 所以真正要建的不是"一次大优化"，而是**对抗漂移的机制 + 数据驱动的决策回路**。

---

## 一、先把一个词拆成三件事

你说"最新、最准确、最适合"，这其实是三种东西，节奏和负责人都不一样：

| 维度 | 本质 | 变化速度 | 靠什么保证 | 失败表现 |
|---|---|---|---|---|
| **最新** | 技术层：模型 / 检索 / Prompt 工程 | 快（月级） | 技术雷达 + 小步 A/B | 追新引入不稳定 |
| **最准确** | 效果层：指标可量化 | 中（周级） | Benchmark + Gate | 凭感觉说"更准了" |
| **最适合我们公司** | 业务层：口径 / 表 / 规则 / 组织 | 慢（季度级） | 知识资产化 + 责任人 | 口径各说各话 |

> ⚠️ 最常见的错误：拿"最新"的手段去解决"最适合"的问题（比如反复换模型，却不更新指标口径）。
> **对知数AI 而言，价值 80% 在"最适合"（口径与知识），而不是"最新"。**

---

## 二、真正的敌人是「漂移」——四类漂移与各自防线

| 漂移类型 | 具体表现 | 现有防线 | 缺口（要补） |
|---|---|---|---|
| **数据漂移** | 表改名、字段增删、字典值变化 | `check_consistency.py`（知识库↔真实库） | 定期跑 + Schema 快照 diff + 变更告警 |
| **模型漂移** | DeepSeek 版本升级、API 行为变化、额度/限流 | `evaluate.py --regression` | **模型变更必跑 Regression**（固化为例行） |
| **知识漂移** | 指标口径过时、业务规则调整 | Metric Registry（可编辑） | 口径**版本化 + 评审记录**（谁改的、为何改） |
| **需求漂移** | 业务问题变了，测试集失去代表性 | Golden Dataset | **线上真实错误回流**（最重要的一环） |

> 记忆点：**前三类靠"检测"，第四类靠"回流"。** 没有回流的评测集，半年后就会和真实业务脱节。

---

## 三、持续优化闭环（6 步，每步都留痕）

```
① 发现（线上反馈 / 日志 / 用户报错 / 巡检）
        ↓
② 建用例（把问题固化成 Golden/Regression 用例，先红后绿）
        ↓
③ 定位（错误分析：Error Analysis 分类，找贡献最大的错误类型）
        ↓
④ 提出方案（改知识 / 改检索 / 改 Prompt / 改校验——按代价从低到高）
        ↓
⑤ 评测（python evaluate.py --regression --gate，出 Before/After/Delta）
        ↓
⑥ 发布或打回（Gate 通过才发；打回则回到 ③）
        ↓
     线上运行 → 新问题 → 回到 ①（形成回流）
```

**铁律**：没有 ② 的用例，不允许进入 ④ 改代码。否则就是"改了但说不清好在哪"。

## 四、分层优化策略（不要所有东西都用同一种节奏改）

| 层 | 内容 | 变化速度 | 治理强度 | 改动后必须做什么 |
|---|---|---|---|---|
| **内核** | 指标口径、业务规则、实体/关系 | 慢 | 最严（需评审） | 全量 Regression + 口径评审记录 |
| **中层** | 检索策略、阈值、校验规则、时间解析 | 中 | 中（评测驱动） | 跑 Golden + Ablation |
| **外层** | Prompt 措辞、模型版本、参数 | 快 | 轻（可 A/B） | 跑 Golden + 看 Delta |

> 越靠内核，越不能"快速试错"；越靠外层，越鼓励小步快跑。
> **把内核当外层改，是口径事故的根因。**

## 五、逐环节优化抓手（对照生产链路）

| 环节 | 怎么知道它好不好 | 持续优化抓手 |
|---|---|---|
| 时间口径解析 | Time Accuracy + boundary 数据集 | 补节日表、加相对时间表达（每发现一类加一例） |
| 查询理解 | Intent / Metric Accuracy | 补同义词（"妥投量"）、补别名，喂 few-shot 例 |
| 语义层路由 | Metric/Table Recall + forbidden 指标 | 补实体、补关系、修实体过滤（防跨业务线误召回） |
| 混合检索 | Table/Field Recall | 调阈值（用 Ablation 定值）、补字段注释 |
| 提示组装 | 消融 Prompt 看 Delta | Prompt 版本化，改动需 A/B |
| SQL 生成 | SQL Accuracy | 补口径断言用例、把"已知错误模式"写成 P0 规则 |
| SQL Validator | Exec Success + 拦截率 | 每发现一个 CH 语法坑（如 `dateTrunc('MONTH')`）加一条校验 |
| 执行 | Exec Success Rate | 表权限、依赖表可见性、超时/内存参数 |
| Result Validator | Result Accuracy + 用户反馈 | 把"静默算错"的形态加入结果体检 |
| 拒答 | Abstention Accuracy | 记"该拒没拒"和"不该拒却拒"两类，分别调 |
| 答案生成 | Grounding + Hallucination | 答案与 SQL 结果数值对齐（UNSUPPORTED_CLAIM） |
| 全链路 | Overall + P95 + 成本 | 每轮记录，作为版本基线 |

## 六、三种节奏（把它变成例行工作）

| 节奏 | 做什么 | 命令 |
|---|---|---|
| **每次改动** | 跑 Golden + Regression，不过不上线 | `python evaluate.py --regression --gate` |
| **每周** | 跑全部数据集（golden/abstention/adversarial/boundary…），看错误分布变化 | `python evaluate.py --dataset evaluation/datasets` |
| **每月** | 跑 Ablation + Consistency，产出模块贡献度与稳定性报告 | `run_ablation.py` / `run_consistency.py` |
| **触发式** | 模型版本变更 / 表结构变更 / 口径调整 → 必跑全量 | 同上 + `check_consistency.py` |

## 七、防止「越优化越乱」的红线

1. **禁止针对测试集硬编码答案**（Test Set Leakage）。测试集不进生产 Prompt。
2. **禁止无数据改核心**（口径/规则/实体）。必须先有用例、先看到红。
3. **禁止绕过 Gate 发布**。核心指标退化一律打回。
4. **禁止凭主观声称"更准了"**。一切以 Before/After/Delta 为准。
5. **禁止拿消融结果直接删模块**。消融是诊断，删除要过 Regression + Release Gate；
   安全模块（guard / table_acl / 停用指标拦截 / 兜底拒答）**永不消融**。
6. **禁止只优化"能测的"**。有些价值不在 accuracy（如 result_validator 的风险提示），
   需用多维度（拒答/幻觉/延迟/体验）综合判断。

## 八、知识资产化：让"最适合我们公司"沉淀下来

AI 取数真正的护城河不是模型，而是**公司的口径资产**：

- **Metric Registry**：每个指标 = 定义 + 来源表 + 过滤条件 + 聚合 + 同义词 + 业务域
- **Business Rule Registry**：状态/身份/业务线/时间/金额等规则，带优先级与冲突解决
- **实体/关系**：表与表怎么 Join（防笛卡尔放大）
- **字典**：编码 → 中文（防"语法正确、结果全错"）
- **字段注释**：AI 生成的要标"未复核"，人工复核后转正

> 建议：**每一条口径变更都留版本与责任人**。这样"谁在什么时候为什么改了完单率口径"可追溯——
> 这是从"能演示"走向"可治理"的关键。

2. 修 **P6（`dateTrunc('MONTH')` 执行失败）+ P7（依赖表越权）** —— 对 Exec Success 提升最大。
3. ~~建立线上错误回流入口~~ ✅ **已完成（2026-10-08）**：`evaluation/reflow.py`

5. 给 Metric Registry 加**变更留痕**（谁改的、何时、为何）。

## 十、一句话总结

> **"最新"靠技术雷达，"最准确"靠数据说话，"最适合我们公司"靠口径资产化 + 责任人。**
> 三者都不靠一次优化达成，而靠一个能**自动发现问题 → 自动证明效果 → 自动拦住退化**的回路持续逼近。
> 我们已建好这个回路的骨架（Golden + Benchmark + Gate + Ablation），接下来要补的是**回流**与**例行化**。
