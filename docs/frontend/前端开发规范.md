# 知数AI 前端开发规范（V1）

> 版本：V1.0 ｜ 日期：2026-11-17
> 定位：知数AI 全站统一的视觉与工程规范，杜绝「不规则页面」再次出现
> 风格基准：腾讯云 DataBuddy（企业级 AI 数据工作台）——干净、克制、信息分层清晰
> 落地文件：`frontend/static/app.css` 的 `:root`（本次先立规范，代码迁移按 §9 单独排期）

---

## 0. 为什么要有这份规范（先看结论）

知数AI 前端已出现「不规则页面」的典型症状，根因不是某个页面写错了，而是**缺乏一套强制遵守的统一规范**。当前问题集中爆发在「AI 评测」页（`#tab-dash`），但同类问题在其它页同样潜伏。

本规范用三条铁律 + 一套 token + 一组组件红线，让任何新增/修改页面的开发者在动手前就有一份「照着做就不会歪」的约束，而不是靠自觉。

---

## 1. 现状诊断：AI 评测页面的 8 处不规则（代码级证据）

| # | 问题 | 证据位置 | 危害 |
|---|---|---|---|
| 1 | 指标卡网格三种规则并存，`auto-fill` 导致末行卡片拉伸、留参差空隙 | `.stat-grid` `minmax(180px,1fr)` / `.dash-metric-grid` `minmax(170px,1fr)` / `.dash-grid` `minmax(260px,1fr)` | 卡片列不齐、高低不平 |
| 2 | 圆角混用：卡片 10px / 指标卡 8px / 标签 4px / 旧 badge 10px | `.dash-sec` vs `.dash-metric` vs `.status-tag` vs `.badge-*` | 圆角四处不一 |
| 3 | 数值字阶不统一：26px / 22px 并存 | `.stat-val` 26px vs `.dm-val` 22px | 数字大小混乱 |
| 4 | 两套状态标签并存 | `.badge-*`（11.5px 圆角胶囊） vs `.status-tag`（12px 直角） | 同一状态两种长相 |
| 5 | 多种灰色边框混用 | `#e5e6eb` / `#f0f1f4` / `#f2f3f5` | 界面发灰发脏 |
| 6 | 颜色硬编码 437 处，token 只用 24 次 | 全仓 Grep `#` | token 形同虚设 |
| 7 | 语义错用：错误归因条形用主蓝而非警示色 | `.err-fill` background `#165dff` | 错误读成「正常」 |
| 8 | 信息无主次：5 区块 30+ 指标卡等权平铺 | `golden.js loadDashPage()` | 一屏全是卡，无总评 |

**结论**：不是「某页写坏了」，是「没有规范约束写法」。规范落地后，以上 8 条应全部成为「写不出来的状态」。

---

## 2. 三条铁律（不可协商）

1. **只用 token，禁止硬编码**。任何颜色、圆角、间距、字号必须来自 `:root` 变量，`#` 色值、裸 `px` 圆角/间距一律禁止出现在业务代码里。
2. **一个页面只有一个 H1 层级，一个主角**。评测页的主角是「质量总评」；其余信息必须分层收纳，禁止满屏等权卡片。
3. **状态语义固定映射**。绿=成功/正常，橙=待处理/警告，红=错误/危险，蓝=信息/执行中，灰=中性/停用/规划中。颜色不作为唯一识别方式（必须配文字）。

### 3.2 字体与字阶

字体族（保留现状）：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`；等宽族仅表名/字段/SQL。

| Style | 字号/行高/字重 | 用途 |
|---|---|---|
| `--font-display` | 20 / 28 / 600 | 页面标题 |
| `--font-heading` | 15 / 22 / 600 | 模块/卡片标题 |
| `--font-body` | 14 / 22 / 400 | 正文 |
| `--font-body-sm` | 13 / 20 / 400 | 表格正文、表单值 |
| `--font-caption` | 12 / 18 / 400 | 辅助说明、时间戳 |
| `--font-number-lg` | 28 / 36 / 600 | **唯一**大数字（总评、KPI 主值） |
| `--font-number-md` | 20 / 28 / 600 | 次级指标值 |

> **强制**：数字一律 `font-variant-numeric: tabular-nums`，且只允许 `--font-number-lg/md` 两档，禁止再出现 26px / 22px 等散落字号。

### 3.3 间距 / 圆角 / 阴影

| 类别 | Token | 值 | 规则 |
|---|---|---|---|
| 间距 | `--space-1..6` | 4 / 8 / 12 / 16 / 24 / 32 | 卡片内边距 **16**，卡片间 **24**，区块间 **32** |
| 圆角 | `--radius-sm` | 6px | 按钮、输入框、标签 |
| 圆角 | `--radius-md` | 8px | **所有卡片/面板/表格（唯一档）** |
| 圆角 | `--radius-lg` | 10px | 弹窗、抽屉 |
| 阴影 | `--shadow-card` | `0 1px 2px rgba(29,33,41,.04)` | 常规卡片（极克制，默认可无） |
| 阴影 | `--shadow-float` | `0 8px 24px rgba(29,33,41,.10)` | 抽屉、弹窗、下拉 |

> **强制**：卡片统一 8px 圆角（不再混 10px）；边框统一 `--color-border`（不再混 `#f0f1f4`/`#f2f3f5`）。

### 3.4 布局栅格

```
┌──────────┬─────────────────────────────────────────────┐
│ 侧栏     │ 顶栏 56px：标题 · 说明 · 主操作（≤1）          │
│ 232px    ├─────────────────────────────────────────────┤
│ 5 分组    │ 页面头：H1 + 一句说明 + 主操作               │
│          ├─────────────────────────────────────────────┤
│          │ 工作区（max-width 1180，中央留白对齐）         │
│ 底部身份 │  评测页专用：总评 Hero + 12 列固定栅格分区      │
└──────────┴─────────────────────────────────────────────┘
```

**固定栅格（关键，根治「不规则」）**：网格一律用固定列数，**禁用 `auto-fill`**：

| 断点 | 栅格 |
|---|---|
| ≥1440px | 12 列（KPI 卡 4 列 / 指标卡 6 列 / 分区 2 列） |
| 1200–1439px | 指标卡 4 列、分区 2 列 |
| 992–1199px | 指标卡 3 列、分区 1 列 |
| 768–991px | 指标卡 2 列 |
| <768px | 单列 |

## 4. 组件红线（对照 §1 的 8 条，逐条封死）

| 组件 | 强制规则 |
|---|---|
| **Card / Panel** | 白底 + `--color-border` 1px + `--radius-md` 8px + 内边距 16px；**默认无阴影**；同一层级卡片样式完全一致 |
| **MetricCard 指标卡** | 数值只用 `--font-number-md`；标签 `--font-caption`；口径说明折叠到 `title` 或底部一行；**不用彩色顶边** |
| **StatusTag 状态标签** | 全站唯一标签组件 `.status-tag`；废弃 `.badge-*`/`.rv-chip`/`.trust-chip`/`.tag`；圆角 `--radius-sm` |
| **Button** | `primary`(蓝) / `secondary`(白描边) / `danger`(红) / `text`；主按钮每屏 ≤1；尺寸 32/40 两档 |
| **Table** | 表头 `--color-bg-subtle`、13px；长文本换行；数值右对齐；无横向溢出 |
| **Bar 条形图（错误归因）** | 填充色用**语义色**（红/橙），禁用主蓝；计数右对齐 + tabular-nums |
| **Drawer / Modal** | 抽屉 480px 右侧、弹窗居中 480–640px；`--radius-lg`；ESC/遮罩关闭 |
| **Empty / Loading / Error** | 空状态=原因+可执行动作；加载=骨架屏；错误=原因+下一步，不暴露技术异常码 |
| **Toast** | 右上角 3s 自动消失，`success/error/info` 三态 |

## 5. 评测页（AI 取数质量中心）专项模板

这是本次整改的示范页，也是后续所有「看板/评测/数据页」的参照模板。

**结构（自上而下）**：

1. **页面头**：`H1「AI 评测」` + 一句副标题 + 右侧主操作「刷新」（次级「查看评测报告」用文字按钮）。页面内不再重复「AI 取数质量中心」大标题（顶栏已显示页名，避免层级重复）。
2. **总评 Hero（唯一主角）**：左侧一个大号综合得分（`--font-number-lg` 28px）+ verdict 标签（「良好/需改进/告警」）+ 一句话解读；右侧 3 个关键分项（SQL 生成成功率 / SQL 执行成功率 / 业务结果准确率，`--font-number-md`）+ 数据更新时间。
3. **分区（12 列固定栅格，两列排布）**：
   - 核心运行概况（4 KPI）
   - 错误归因分析（红/橙警示条形，12 类统一分类）
   - AI 评测质量（按「核心准确率/检索与知识依据/执行与结果/性能开销」四组折叠）
   - 知识资产质量 / 反馈与持续优化（合并为一行）
4. **技术细节默认收纳**：SQL、校验报告、查询理解等默认折叠，不占首屏。

**该模板的三条硬规则**：① 总评 Hero 全局唯一；② 指标卡不得少于 4、不得多于 8，超出则分组折叠；③ 无真实数据时数值显示「—」并注明「需接入真实口径」，禁止编造。

## 6. 文案规范

- 账号相关统一「密码」，禁用「口令」。
- CTA 用主动语态，按钮说什么、Toast 就说什么（「发布」→「已发布」）。
- 错误与空状态用界面口吻指引下一步，不道歉、不模糊。
- 状态标签必带文字（颜色不作唯一识别）。

## 8. 与既有规范的关系

本规范是 `docs/frontend/design-system-v2.md` 的**落地收口版**：V2 定义了「要什么气质」，本规范定义了「怎么强制落地、哪些写法禁止」。二者冲突时以本规范为准。`component-guidelines.md` / `page-guidelines.md` 中与 §4/§5 冲突的旧写法（如 `.badge-*`、`auto-fill` 网格）一律按本规范废弃。
